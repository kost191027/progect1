# RKN 0.1.9

RKN 0.1.9 focuses on multi-device control, transport fallback, and runtime stability after the 0.1.8 multi-platform release.

## Highlights

- Added the master/subordinate resolver model for real multi-device use:
  - master installations can manage and switch between saved server profiles;
  - master installations can add new servers without losing the active workflow;
  - subordinate installations can import and use multiple invite/phone links without SSH credentials.
- Added VLESS/Reality as an additional transport path alongside the existing ShadowTLS/Shadowsocks stack.
- Added transport selection state so a client can distinguish the active ShadowTLS path from a provisioned VLESS path.
- Added server-side and client-side bootstrap support for VLESS-capable profiles.
- Improved Android runtime stability:
  - cleaner startup and shutdown around the native backend;
  - better recovery handling around network changes and backend state;
  - Android runtime config can route protected traffic through VLESS when available;
  - gameplay/UDP-sensitive Android paths avoid unstable multiplex behavior on VLESS.
- Improved macOS stability around active tunnel recovery, stale runtime cleanup, and transport sync checks after startup.
- Improved invite and link management:
  - faster invite generation from cached bootstrap state;
  - link regeneration for VLESS-capable subordinate clients;
  - clearer master/subordinate UI wording for desktop and Android.
- Improved server/deploy behavior:
  - multi-server library groundwork;
  - better server profile switching;
  - deploy script compatibility for the expanded transport state.

## Notes

Existing ShadowTLS-only servers and clients remain supported. VLESS is introduced as a fallback/alternate transport path, not as a forced replacement for the current primary transport.
